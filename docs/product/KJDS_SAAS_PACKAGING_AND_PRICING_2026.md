# KJDS SaaS 产品分层、运营模式与定价策略（2026）

> 版本日期：2026-07-25
> 适用市场：以中国跨境团队经营 Ozon 为首发场景；价格为人民币含税建议零售价，最终税率、支付通道和合同主体由法务与财务确认。

## 一、产品原则

KJDS 只维护一套事实、利润、Evidence、决策、审批和执行内核。客户规模通过套餐额度与治理能力区分；店群、铺货、精品/精细化和品牌运营通过工作区模板区分。不能为了批量或低价套餐复制数据表、计算器或弱化安全门。

商业承诺必须与已交付能力一致：

- “分析、建议、审批、执行”四种状态明确分开。
- 未完成真实 Ozon 连接、回读和止损验证前，只售卖只读分析与建议，不宣传自动改价、自动投放或自动上架。
- 1688 展示价只作选源线索或估算，不宣传为实际落地成本。
- 套餐升级只增加额度、协作、自动化和服务等级，不改变历史数据归属与审计链。

### 上市初期优惠

- 14 天试用：无需绑卡；1 个演示店或 1 个只读店，最多 50 个 SKU。
- 试用期不开放外部写入、采购、广告花费或批量发布。
- 首批 30 家“共创客户”可锁定 12 个月 7 折，但必须同意结构化访谈、产品使用数据分析和案例授权另行选择。
- 季付 95 折、半年付 9 折、年付约 83 折；不建议长期做 3 折或永久免费，以免支持成本和客户质量失控。

## 三、运营工作区

运营模式不是独立套餐。Growth 及以上可以在同一店铺中启用多个工作区，Scale/Enterprise 才解锁跨店组合。

| 模式 | 适合谁 | 首页重点 | 核心流程 | 关键门禁 |
|---|---|---|---|---|
| 小白引导 | 首次经营 Ozon | 今日 3 个任务、术语解释、缺失资料 | 连接店铺→选择商品→核对成本→完善内容→形成首个实验 | 不允许跳过 Evidence、成本和合规 |
| 铺货运营 | 多 SKU 测款、快速上新 | 待上新池、重复商品、零动销、淘汰队列 | 1688 候选→去重/侵权筛查→批量成本预估→小批测试→14/30 天淘汰 | 批量不等于自动发布；无最小证据不进池 |
| 精品/精细化 | 少量核心 SKU、追求利润 | SKU 贡献利润、转化漏斗、内容评分、广告承受力 | 全成本→同行价格带→七角色内容→自然转化→限额广告实验→复盘 | 无实际成本、真实转化或止损线不放量 |
| 店群运营 | 多店、多账号、多团队 | 跨店利润、重复铺货、账号风险、额度占用 | 店铺隔离→商品策略复制→本地化差异→跨店库存/价格冲突→组合风控 | 禁止跨店凭证、Evidence 或客户数据串用 |
| 品牌运营 | 品牌方、授权经销 | 品牌资产一致性、内容合规、渠道价格 | 资产库→授权与声明→多语言审校→渠道规则→审批发布 | 品牌、商标、宣传声明必须有权威证据 |

### 模式专属功能补充

店群：

- 店铺分组、法人/主体、地区、币种、负责人和风险预算。
- 跨店商品映射与重复铺货提醒，不自动合并不同店铺事实。
- 模板复制只复制策略，不复制凭证、实际销量或权限。
- 按店铺、团队和动作设置日额度、Kill Switch 与审计导出。

铺货：

- 批量候选导入、相似商品聚类、重复/侵权/禁限售预检。
- 以“观察池→测试池→保留池→淘汰池”管理生命周期。
- 上新速度、首单时间、14/30 天动销、退货和 CM3 作为淘汰依据。
- 先做小批量和影子建议；批量发布仍需可追溯批准和回读。

精品/精细化：

- 商品级全成本、目标 CM3、P25/中位数/P75、最大 ACOS/CPC。
- 搜索词、点击、加购、转化、评价、退货、缺货和广告分层诊断。
- 主图、尺寸、结构/材料、使用场景、包装、售后等角色化内容计划。
- 每次价格、内容或广告变化只能进入一个有基线、预算、观察期和止损的实验。

品牌：

- 品牌素材库、授权期限、声明白名单/禁用词、渠道价格策略。
- 多语言原生复核、素材版本、内容审批和撤回。
- 服务商代运营时，客户组织拥有数据，服务商只获授权范围内访问。

## 四、计费口径与加购

基础计费采用“唯一卖家店铺 + 活跃 SKU 档位 + 包含席位”，不按 GMV 抽成。GMV 抽成会让客户担心系统与其利益不一致，也难核对退款、税费和跨币种。

建议加购：

- 额外店铺：Starter ¥199/月，Growth ¥299/月，Scale ¥399/月；超过 Scale 范围转企业合同。
- 额外 1,000 活跃 SKU：¥299/月；10,000 以上采用阶梯报价。
- 额外席位：¥99/人/月；只读审计席位可按 50% 价格。
- AI 内容/图片：套餐含月度额度，超额按任务包计费；展示预估消耗并允许硬上限。
- 定制数据连接器：¥10,000–¥80,000/个起，另计第三方 API 或代理成本。
- 标准上线服务：Growth ¥3,000，Scale ¥10,000；包括数据模板、权限设计、一次培训和首个经营闭环。
- 代运营或人工商品制作不混入 SaaS 订阅，单独签服务合同和验收口径。

“活跃 SKU”定义为计费周期内被同步、分析、生成内容、创建任务或纳入实验的唯一 SKU；仅保留历史、不再运行的 SKU 不计费。唯一店铺按平台 Seller Cabinet/Client ID 计数，重新授权同一店铺不能重复计费。

## 五、不同套餐的权限与自动化

| 能力 | Starter | Growth | Scale | Enterprise |
|---|---|---|---|---|
| 所有核心模块可见 | 是 | 是 | 是 | 是 |
| 店铺事实、利润、内容建议 | 是 | 是 | 是 | 是 |
| 铺货/精细化模板 | 精简 | 完整 | 完整 | 完整+定制 |
| 跨店组合与店群 | 否 | 只读汇总 | 完整 | 完整 |
| 用户、角色、双人审批 | 1 人确认 | 基础角色 | 完整 RBAC | SSO/组织策略 |
| 批量任务 | 20 条/批 | 500 条/批 | 5,000 条/批 | 协议额度 |
| API 与数据导出 | 基础 CSV | CSV/定时报表 | API/Webhook | 专属集成 |
| 外部写入 | 不开放 | 经平台能力和审批逐项开放 | 经平台能力和治理开放 | 合同与安全评审后开放 |
| 支持 | 知识库/工单 | 工作日支持 | 优先支持/季度复盘 | SLA/专属成功经理 |

“所有核心模块可见、按额度与治理差异收费”能减少套餐理解成本。当前 [MPSTATS 官方产品更新](https://mpstats.io/media/mpstats/news/produktovye-obnovlenija-za-maj-2026-goda)也采用三档套餐、全部模块开放、以独立店铺和员工数量区分的思路；KJDS 可借鉴计费结构，但不能照搬其功能声明或价格。

## 六、市场锚点与定价判断

以下只用于 2026-07-25 的市场锚定，不代表功能完全可比：

- [MPSTATS 官网](https://mpstats.io/)展示新套餐从 6,495 RUB/月起，覆盖 Ozon、Wildberries 和 Yandex Market，并提供测试期。
- [Mayak 官网](https://mayak.bz/)展示 3 个月 39,000 RUB、6 个月 59,000 RUB 的组合，包含内外部分析、SEO、repricer、单元经济、供应与评价等能力。
- [Sellerfox 官方定价](https://sellerfox.com/en/pricing/)采用工作区计费，标准版 €39.99/月，Agency 以最少 15 个工作区起售，并提供 30 天试用。
- [Analitika Marketpleysov 定价页](https://analitika-marketpleysov.ru/pricing)展示从 2,490 RUB/月到 15,000 RUB/月的层级，以及额外平台和用户加购。

据此，KJDS 不应以“低价数据工具”定位。它的差异是把成本权威、Evidence、商品内容、组合决策、审批和有限执行放在一条可追溯链中。Starter 负责降低首次使用门槛；Growth 应成为主销套餐；Scale 通过店群治理、团队协作和批量能力贡献主要毛利；Enterprise 通过集成、隔离、SLA 和实施服务定价。

## 七、销售与转化路径

### 小白

销售主张：“不用先学会全部跨境术语，系统每天告诉你先补什么事实、为什么不能投广告。”

转化事件：完成首店连接、录入首个真实成本场景、生成首个 SKU 方案、形成第一项人工任务。试用期不以“出了多少建议”衡量，而以完成首个可信闭环衡量。

### 中小卖家

销售主张：“把表格、素材、价格和广告判断集中到一个全店利润工作台。”

转化事件：导入 20–100 个 SKU、识别零动销/成本不具竞争力商品、形成一周可执行任务、减少手工对账时间。

### 大卖家/店群

销售主张：“不同店铺仍然隔离，但老板能看到跨店利润、风险和执行额度。”

成交前提供只读诊断；正式合同包含权限矩阵、店铺清单、数据迁移、验收指标和回滚演练。POC 不应获得生产批量写权限。

### 企业

销售主张：“把多团队、多法人、多店铺经营变成可审计、可止损的经营控制面。”

采用年度合同、实施费和明确 SLA；先完成安全/数据评审，再承诺 SSO、私有网络、保留策略、灾备和定制连接器。

## 八、上市前必须补齐的产品化能力

当前工程闭环不等于已经可以公开售卖。商业上线前至少完成：

1. Tenant、Organization、Store、Membership、Role 的强隔离模型。
2. Subscription、Entitlement、Usage Meter、Invoice/Payment 状态和宽限期。
3. 店铺凭证加密、轮换、撤销、最小权限与连接健康页。
4. 租户级审计、数据导出/删除申请、保留策略、备份恢复和事故通知。
5. 套餐额度在服务端执行；前端隐藏按钮不能替代权限与配额检查。
6. 新手引导、演示数据、空状态、术语帮助、导入校验和可恢复失败。
7. 真实计费渠道、发票、服务协议、隐私政策、数据处理协议和退款规则。
8. 客户支持后台、状态页、工单、操作手册和版本发布说明。
9. Ozon/1688 等平台条款与数据许可由法务确认；客户接受平台条款不能替代 KJDS 自身合规责任。
10. 至少 3 家不同规模先锋客户完成“连接→事实→建议→人工执行→结果回读→利润复盘”，再公开宣传自动化收益。

## 九、商业指标

首年建议跟踪：

- 试用到付费 ≥ 12%，完成首个可信闭环的试用客户转化 ≥ 25%。
- Starter→Growth 90 天升级 ≥ 15%。
- Growth/Scale 月度净收入留存 ≥ 100%，企业年度续约 ≥ 85%。
- 软件毛利率目标 ≥ 75%；AI、代理、人工支持与第三方 API 成本必须进入套餐单位经济。
- P0 工单首响：Starter 1 个工作日、Growth 8 工作小时、Scale 4 工作小时、Enterprise 按 SLA。
- 不以“自动执行次数”作为北极星指标；使用“有证据的经营决定完成率”和“完成观察期的增量 CM3”衡量价值。

## 十、推荐发布顺序

1. **Design Partner**：5–10 家，手工实施，只读/建议模式，验证事实采集和定价意愿。
2. **Private Beta**：30 家，Starter/Growth 两档，开通订阅、租户隔离、额度和支持流程。
3. **Commercial Launch**：增加 Scale、店群、公开定价、标准实施包和案例。
4. **Enterprise**：完成 SSO、审计导出、SLA、灾备和定制连接器交付模板后再销售。
5. **受控平台写入**：只对完成平台合同验证、审批、单次许可、回读和止损的动作逐项开放，不能按套餐一次性“全部解锁”。
