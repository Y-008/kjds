# ADR-0107：Ozon 经营模式、竞品情报与 AI 工作台

状态：Proposed  
日期：2026-09-07  
范围：KJDS 私有部署，单主体、1–3 个 Ozon 店铺、3–20 个 SKU 的首个可交付切片

## 决策摘要

KJDS 以“经营模式状态机 + 证据驱动的商品生命周期 + 受控执行”作为 Ozon 运营主模型。系统不把跟卖、铺货、精铺、精品、FBA 视为几个互相独立的页面，而是视为同一商品组合在不同风险、数据成熟度和库存承诺下的经营策略。

首期默认路径是：

```text
市场/同行观察 → 候选池 → 合规与侵权筛查 → 供应链与物流核价
→ 小规模测试 → 精铺优化 → 贡献利润验证 → 库存/FBA 决策
→ 复盘、扩量或退出
```

所有自动化动作必须经过 `OBSERVE → DECIDE → PERMIT → EXECUTE → READBACK → REPLAN`。浏览器登录状态不等于 Seller API 运行身份；抖音、同行页面和平台截图只能进入外部观察证据，不能直接成为可发布商品或可记账收入。

## 需求证据及其边界

用户提供的抖音内容集中在以下业务信号：跟卖转精铺、Ozon AI 工作台、减少人工上架、同行店铺监控、批量测款、供应商规格采集、物流和利润核算、图片防侵权、多店铺批量管理。公开检索到的相关文稿也反复强调：跟卖依赖他人链接且存在侵权/封店风险；铺货以数量换概率；精铺强调少量上新、数据选品和持续优化；优质店铺需要持续观察其新品和出单覆盖率；自动化工具常见卖点是供应商参数、运费预估、多店上架和利润统计。[抖音相关检索结果](https://www.douyin.com/shipin/7645510102325512238)、[Ozon优质店铺与热销商品观察](https://www.douyin.com/video/7396307965608725795?source=Googlebot-sdc)、[Ozon AI自动化工具公开介绍](https://www.douyin.com/video/7655353559827680902)

这些来源属于公开内容和销售宣传，不是 Ozon 官方规则或当前账户事实。采集结果必须带 `source_url`、`captured_at`、`source_type`、`content_hash`、`requires_review`；未经人工或规则复核，不得用于自动发布、定价或宣称收益。

## 经营模式状态机

### 跟卖观察（`FOLLOW_OBSERVATION`）

只允许记录商品、卖家、价格、库存可见性、排名和时间序列。系统可计算价格带和竞争密度，但不复制标题、图片、品牌、属性或受保护内容，也不自动创建跟卖关系。任何疑似品牌、图片或文本侵权进入 `COMPLIANCE_BLOCKED`。

### 测试铺货（`TEST_CATALOG`）

允许导入候选商品并建立草稿，但限制批量规模、并发、媒体来源和预算。每个候选必须有供应商、尺寸重量、币种、物流方案、平台费用、预期退货成本和最小贡献利润；缺失字段是 `NO_DATA`，不能用零填充。

### 精铺运营（`PRECISION_STORE`）

首期主路径。每天少量上新，围绕类目、关键词、主图、变体、价格、库存和自然流量做可解释实验。AI 负责候选排序、缺口解释和草稿生成，发布仍由 Permit、读回和回滚约束。

### 精品与品牌化（`HERO_PRODUCT`）

要求有稳定需求证据、差异化内容、知识产权证据、供应链稳定性和风险调整利润。系统维护单品事实图和版本化媒体资产，任何“爆款”结论必须排除缺货截断和实验污染。

### FBA/本地库存准备（`LOCAL_STOCK_READY`）

不是单纯的物流开关。进入前必须通过库存周转、现金占用、退货、税费、认证、仓储和最坏情景压力测试；没有真实结算和库存证据时只能输出决策建议。

状态机允许回退：利润、证据新鲜度、库存或合规状态恶化时自动降级到观察或暂停，不允许“已发布”状态掩盖后续风险。

## 领域模型

新增或统一以下实体：

```text
MarketObservation        外部商品/店铺/内容观察
CompetitorStore           同行店铺画像与时间序列
CandidateProduct          候选商品及来源证据
ProductVersion            标题、属性、媒体、价格的不可变版本
SupplierOffer             供应商报价、规格、询价回执
LogisticsScenario         线路、体积重、时效、费用和置信度
ProfitScenario            销售价、平台费、采购、物流、广告、税费、退货准备金
Experiment                控制组、处理组、暴露窗口和污染策略
ComplianceReview          品牌、图片、文本、认证和地域风险
ListingDraft              草稿、校验结果、Permit 和回读
InventoryCommitment       采购/备货/FBA承诺、现金和库存风险
ContentAsset              原图、改图、视频、字幕、版权和成本归属
EvidenceBundle            原始响应、文件、哈希、导入、规则和决策链
OperatingDecision         AI建议、依据、反例、经济影响和回滚路径
```

每个实体使用 `tenant/entity/store/warehouse/sku` 作用域，使用 `event_time/observed_time/effective_time/settled_time` 四时间字段，所有修订追加版本，不覆盖原事实。

## AI 工作台

AI 工作台不是一个聊天框，而是按业务任务驱动的队列和项目图：

1. **情报 Agent**：接收 Ozon 观察、公开网页、抖音链接和人工导入，生成去重后的观察卡片；不能把外部内容当作平台事实。
2. **同行 Agent**：维护店铺名单、类目覆盖率、上新速度、价格分布、出单代理指标和变化告警；只展示可验证字段。
3. **选品 Agent**：将需求、库存可得性、竞争密度、供应商质量、物流和风险调整利润合成候选评分；明确置信区间和缺失数据。
4. **内容 Agent**：生成中文工作稿和俄文候选稿、图片/视频任务、关键词和属性映射；版权、品牌和事实字段必须进入人工/规则复核。
5. **利润 Agent**：输出实时利润、结算利润、风险调整利润和现金占用，追踪迟到结算、退款、拒付和汇率版本。
6. **运营 Agent**：编排实验、价格建议、库存阈值、广告预算和发布草稿；自动执行能力受 Permit 和经济护栏约束。
7. **项目经理 Agent**：读取 HEAD、图快照、节点状态、证据新鲜度、租约、队列、测试和回读，生成最小阻塞集和下一波任务。

统一输出：`task_result/changed_files/proof_refs/evidence_refs/test_receipts/new_blockers/invalidated_nodes/economic_impact/rollback_ref/next_dependencies`。

## 页面和交互重构

前端以 UI2 `AppShell + ScopeBar + StatusBadge + DataTable + EvidenceDrawer` 为基础，页面顺序按经营决策而不是技术模块排列：

```text
经营总览
├─ 今日待办与阻断
├─ 店铺/仓库/现金/利润
商品工厂
├─ 情报与同行
├─ 候选池与选品评分
├─ 供应商/物流/利润测算
├─ 内容与媒体资产
├─ 草稿、实验、发布回读
经营分析
├─ SKU/类目/店铺/仓库穿透
├─ 动销、缺货截断、爆款和长尾
├─ 实现利润与风险调整利润
治理与运行
├─ 项目图、证明债务、证据血缘
├─ Ozon 外部事实验收
├─ Permit、租约、预算、卡死任务
└─ 回放、修订、灾备和审计
```

每个指标都能从集团/主体下钻到店铺、仓库、SKU、订单/费用/广告，再到原始证据和外部响应。`NO_DATA/PARTIAL/STALE/BLOCKED/UNKNOWN_OUTCOME/VALID` 永远与数值分开显示。

## 数据和规则

候选评分至少包含：需求证据、可售率、缺货时长、竞争密度、价格弹性、供应商稳定性、物流置信度、内容完整度、侵权风险、预期退货、现金占用和风险调整利润。任何排序都保留特征版本、规则版本、模型版本、输入证据和反例。

实验必须绑定控制组和处理组，价格、广告、主图、标题、库存变更之间设置污染策略。缺货期间销量低只能标记为需求截断，不得直接归类为低需求。实验未结束时不进入长期趋势。

## 自动化边界

默认自动化：抓取/导入、去重、字段标准化、历史重算、报表、告警、草稿、影子定价、实验分组建议和失败恢复。  
受控自动化：Ozon 读操作、价格/库存同步、广告调度、草稿发布和外部回读，必须具备精确作用域、Permit、预算、幂等、读回和回滚。  
阻断自动化：主体身份、资金路径、权限策略、品牌/侵权判断、重大库存承诺、税务结论和生产发布失败后的继续写入。

系统永远显式展示 `external_write_allowed=false`、`formal_fact_promotion_allowed=false`、`production_release_allowed=false`，直到一次性的治理配置、运行身份、证据和经济护栏全部满足。

## 交付顺序

```text
S0  经营模式状态机、实体/四时间/证据协议
S1  情报与同行观察、候选池、供应商/物流/利润测算
S2  精铺工作台、内容资产、实验与缺货需求修正
S3  Ozon 影子读、外部事实验收、回读与回放
S4  受控 Permit、价格/库存/广告草稿和回滚
S5  多店铺、库存/FBA压力测试、现金与售后长尾
S6  Skill、生图、视频、API 用量计费和 SaaS 租户隔离
```

每个阶段必须交付代码、数据迁移、契约测试、反例测试、运行回执、证据快照和回滚演练；“页面能打开”不算阶段完成。
