# ADR-0026：EvidenceOps Copilot 独立产品入口与深模块 seam

- 状态：Accepted
- 日期：2026-07-26
- 决策 Owner：产品负责人、经营负责人、工程负责人
- 影响范围：产品入口、经营简报、经营分析、Agent 任务合同、Web
- 决策合同：`best_solution/1.0.0`
- 首发版本：`0.54.0`

## 背景

LinkFox 等公开跨境 AI 产品把“自然语言目标 → 多工具调用 → 报告/素材”做成低门槛入口，
但厂商公开页面不能证明 Ozon 真源、事实晋升、成本权威、独立审批、执行回读或最终经营
结果。KJDS 已有 Evidence、Gate、经营简报、经营分析、受控执行和财务链，但用户仍需先
理解十个工作区，才能把一个经营目标翻译成正确的补证和任务顺序。

用户于 2026-07-26 明确批准启动更前沿的独立 AI 工具。该批准允许新增独立产品入口，不
允许绕过现有单店先锋范围、建立第二经营真源或把模型文本变成经营事实。

## `best_solution` 评估

| 方案 | 硬约束 | 长期风险调整价值 | TCO / 运维 | 最大损失与可逆性 | 结论 |
|---|---|---|---|---|---|
| A. 复制 LinkFox 式通用聊天与工具市场 | 失败：会引入未准入数据源和隐式权限 | 功能表丰富，可信经营价值低 | Provider、会话、工具和权限面持续膨胀 | 错误工具调用或事实污染；删除成本高 | 淘汰 |
| B. 单独建设 Copilot 数据库和工作流引擎 | 失败：形成第二真源和第二控制面 | 未来可独立扩展 | 同步、对账、迁移和运维成本最高 | 状态漂移影响经营判断 | 淘汰 |
| C. 在现有页面增加一个自由文本框 | 通过基础安全约束，但接口浅 | 入口快，页面继续承担规划逻辑 | 前端重复 Gate、排序与 Agent 映射 | 浏览器漂移；可逆但不可维护 | 淘汰 |
| D. 新增无状态只读深模块和独立产品入口 | 通过：共享身份、真源和控制链 | 自然语言入口与可信任务合同兼得 | 无迁移、无新依赖、一个接口 | 最大损失限于只读建议；单提交可回滚 | 选择 |
| E. 不行动 | 安全但不满足已批准产品目标 | 用户继续手工翻译目标 | 零开发成本，高认知和误用成本 | 无技术损失，竞争差距持续 | 淘汰 |

敏感因素：如果真实使用证明必须保存跨会话计划、支持多租户隔离或调用外部模型，方案 D
仍保留为任务合同核心；持久化、租户和模型 Provider 分别需要新 ADR、数据删除/导出合同、
能力经济评估和生产准入，不在首版隐式增加。

## 决策

新增 `EvidenceOpsCopilot.plan(objective, store_ref)`。这是调用方和测试共同使用的唯一外部
interface；实现内部只依赖两个现有只读模块：

1. `OperatingAnalyticsService.snapshot(store_ref)` 提供阶段、覆盖、焦点 Listing 和数据缺口。
2. `OperatingWorkbenchService.snapshot(limit)` 提供来源化任务、责任 Agent 和运行优先级。

模块隐藏以下复杂性：

- 目标规范化与有界意图解释；
- 已验证事实、未知项和用户目标的类型分离；
- 按目标相关性、现有风险和阶段顺序生成任务合同；
- 每项任务的来源、责任 Agent、当前/目标、工作区和验证条件；
- 固定控制包和规范化 SHA-256。

首版的“Copilot”是确定性规划内核，不调用外部模型。这样可以先建立可评测 Oracle；未来
模型规划器只能作为内部 seam 的 challenger adapter，与确定性结果影子对照，不能改变
外部 interface、事实类型或执行权限。

## 产品 seam

- 独立入口：`/evidenceops`。
- 只读接口：`POST /v1/evidenceops/plan`。
- 输入：一个明确目标和店铺作用域。
- 输出：目标摘要、意图、事实、未知项、任务合同、Agent 状态、控制包和计划哈希。
- 继续操作：导航到既有 KJDS 工作区；Copilot 不拥有领域写接口。
- 身份：复用既有服务端 Web identity；浏览器不接触 API Key。

## 固定边界

- `objective` 是用户意图，不是 Evidence、事实、批准或执行许可。
- 任务合同只解释和排序，不创建 Product、报价、采购、Listing、广告或付款。
- 不自动联系供应商，不自动改价、发布、投放或写 Ozon。
- 不把 LinkFox 或任何第三方营销数据晋升为 KJDS 事实。
- 不保存会话，不建立向量库、Agent 市场、第二数据库或第二权限面。
- 缺真实数据必须显示 unknown/no-data，不能生成演示经营数字。

## 验收与复核

首版必须通过：

- 模块 interface 测试覆盖输入校验、事实/未知分离、目标相关排序、稳定哈希和全部禁止动作；
- API 身份、角色和 OpenAPI 合同测试；
- 独立 Web 入口的 loading/error/empty/success、响应式和构建验证；
- 真实 Docker 快照 smoke 与桌面/移动截图；
- 既有后端、Web、数据库和 secrets 门禁。

以下任一条件触发复审：

- 需要保存会话或计划；
- 引入外部模型、MCP 工具或第三方数据源；
- 允许任务合同产生真实副作用；
- 支持第二店铺、第二平台或多租户；
- 任务排序在真实评测中持续低于人工基线。

最迟于 2026-10-26 复核本 ADR。
