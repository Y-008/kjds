# ADR-0025：经营流转分析只读投影

- 状态：Accepted
- 日期：2026-07-26
- 决策 Owner：产品负责人、经营负责人、工程负责人
- 影响范围：经营总览、Ozon 目录、增长、供应链、执行、财务
- 决策合同：`best_solution/1.0.0`

## 背景

KJDS 已有 Evidence、Readiness、Ozon Catalog、Growth、RFQ、受控执行和财务领域真源，但前台主要按
表单和领域面板展示。操作者需要在多个页面之间自行拼出“当前在哪一步、为什么停住、下一步去哪”
的答案，也看不到真实商品、漏斗、价格带、媒体构成和事实覆盖图。

参考素材和公开竞品页面普遍强调“选品—采购—内容—刊登—监控”的顺滑叙事，但营销截图不能证明
真实数据、利润、权限或外部动作。驾驶舱必须提高可读性，同时继续让缺失数据保持缺失。

## `best_solution` 评估

| 方案 | 硬约束 | 长期风险调整价值 | TCO / 运维 | 最大损失与可逆性 | 结论 |
|---|---|---|---|---|---|
| A. 浏览器从现有三十余接口自行聚合 | 失败：会复制 Gate、优先级和计数语义 | 短期出图快，长期漂移高 | 页面耦合和重复请求持续增长 | 误导经营判断；回滚需拆除页面逻辑 | 淘汰 |
| B. 新建可写 BI 仓库与 ETL | 失败：当前没有历史规模或独立事实库 Owner | 未来可能支持长期趋势 | 新基础设施、同步、补数和对账成本最高 | 双真源和陈旧数据；删除成本高 | 延期到规模证明必要 |
| C. 组合根内新增无状态只读深模块 | 通过：复用现有真源、权限和缺失语义 | 立即形成统一经营解释，并可逐步扩展 | 无迁移、无新依赖；一个服务接口 | 最大损失限于只读展示；单提交可回滚 | 选择 |
| D. 不行动 | 通过安全约束，但不满足可见运营闭环 | 继续增加人工拼接和误读成本 | 零开发成本，高持续人工成本 | 无技术损失，产品验收持续失败 | 淘汰 |

敏感因素：如果日后出现跨租户历史分析、亿级事件扫描或分钟级趋势 SLA，方案 C 的在线组合成本可能
失效，应重新比较物化视图、OLAP 或流式投影。当前只有单店先锋事实，先引入 BI 栈会增加第二真源。

## 决策

新增 `OperatingAnalyticsService.snapshot(store_ref)`，隐藏跨领域读取、阶段映射、覆盖率、漏斗、
焦点 Listing、缺失数据语义和规范哈希：

1. 只调用既有领域服务的只读接口，不直接查询或改写它们的表。
2. Readiness requirement 是 Gate 状态唯一来源；前端不得重算 Gate。
3. 目录、RFQ、发送证明、增长观测、样品单、执行计划和财务分录只贡献“已存在”计数，不自动获得
   更高事实等级。
4. `current/target` 由既有 requirement 或对象计数提供；百分比只作同一指标内的显示换算。
5. 没有真实历史趋势时不返回虚构时间序列；前端展示 `暂无真实历史序列`。
6. 焦点 Listing 优先选择已绑定 Canonical Product 的稳定 offer；媒体仅保留 Ozon 外部引用和
   `unverified_external_reference` 状态。
7. 输出固定 `advisory_only=true`、`platform_write_allowed=false`，并对规范化 payload 计算 SHA-256。
8. Web 使用 HTML/CSS/SVG 呈现漏斗、覆盖率、价格带和媒体构成，所有图表可回到响应中的原始计数。

## 运营模式边界

- 新手引导：把阻断翻译成单一下一步，不降低证据和双人审批。
- 铺货：强调批量去重、目录完整度、失败项和淘汰，不等于批量直发。
- 精细化：强调全成本 CM3、价格带、内容、转化和有上限实验。
- 店群：按店铺隔离身份、预算和风险，再做组合汇总；不得共享平台凭证。
- 品牌：强调权利、素材一致性、复购和长期资产，不把生成图片冒充有权素材。

这些只是同一内核上的视图/策略，不创建五套数据模型或权限体系。

## 复核

以下任一条件触发复审：

- 单次快照读取超过当前页面延迟预算；
- 需要 90 天以上的真实时间序列或跨租户同比；
- 同一经营指标出现两个 Owner 或两个值；
- Ozon 合同/字段使目录或财务聚合语义改变；
- 企业版租户、导出/删除、数据驻留和行级隔离合同获批。

最迟于 2026-10-26 复核本 ADR。正式多租户、BI 仓库和自动平台写入仍需新的独立决定与批准。
