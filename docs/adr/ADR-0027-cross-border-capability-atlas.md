# ADR-0027：俄罗斯优先的全球跨境能力图谱

- 状态：Accepted
- 日期：2026-07-26
- Owner：Product Architecture / Control Plane
- Approver：Project Owner
- 需求：BR-076 / BAS-101

## 背景

LinkFox 公开页面把商品图片、视频、POD、设计器、批量生图、商品/链接/品牌素材、
Skills、Agent、定时任务和 Claw 放在一个低门槛入口。该形态适合作为体验参考，但公开
营销页面不能证明 Ozon 接入、真实经营结果、模型质量、数据许可或生产写权限。KJDS 已有
Ozon/RU 的商品、供应链、CM3、财务、增长、审批、执行和 Evidence 内核，需要一个产品
层能力地图把“覆盖什么、已做到什么、还缺什么、如何扩全球”统一表达。

## 决策

采用一个版本控制的 JSON 注册表与 `CrossBorderCapabilityAtlas` 深模块。注册表不是
菜单清单，而是三层可执行经营语义图：

1. 宏观能力树保留稳定导航 ID；每个叶子包含 LinkFox 公开参考、KJDS 超越点、
   Russia/Ozon 落地、全球扩展、输入、输出、技术策略、状态、市场、平台和控制边界。
2. “点”层把公开套餐页和产品入口继续拆成原子工具，同时补齐 KJDS 的选品、供应链、
   Listing、订单、财务、治理与全球适配点。每点声明父能力、业务对象、操作类型、合同
   profile、具体目标、Evidence、责任人/复核人、失败队列、回读、KPI、SLO、市场、
   平台、控制边界和所属价值流。
3. “线”层定义跨域价值流；每条线必须有有序原子阶段、业务对象状态变化、入口门、出口
   门、领域事件、异常类型、人工接管、SLO、KPI 和平台适配器边界。
4. “面”层定义跨店铺经营控制面；每个面必须回答一组经营决策，声明维度、真源 Owner、
   关联价值流/原子点、指标、预警和写入边界。
5. 服务端在启动时验证全部交叉引用并提供认证只读快照与规范 SHA-256；前端只展示，
   不重算能力状态、价值流顺序、面关系或晋级条件。
6. Web 使用现有 Next.js 16、React 19、TypeScript 5.9、原生 HTML/SVG 和 CSS
   container/query 响应式能力；不为首版引入图数据库或新的可视化依赖。
7. AI 采用提供方中立的多模态适配器、JSON Schema 结构化输出、可复现实验集、
   champion/challenger 影子评测、成本/延迟/质量遥测与人工批准。生成内容不得成为商品事实。
8. Russia/Ozon 是首个实现市场；平台与国家差异通过适配器和版本化规则包隔离，全球扩展
   复用 Canonical Product、Evidence、Passport、CM3、Approval、Execution 和
   Reconciliation。
9. LinkFox 观察统一标记 `evidence_tier=C` 和 `workflow_reference_only`。模型名、套餐、
   调用量、案例和功能文案只是当日公开页面观察，不作为技术或经营事实。

## best_solution 选择

### 选择：版本化注册表 + 服务端只读投影 + 原生 SVG/React

- 长期价值：能力语义、状态和扩展边界可审查、可测试、可 diff。
- 最大损失：静态注册表可能滞后；通过 review date、source URL 和版本哈希控制。
- 可逆性：高；未来若规模证明需要图数据库，现有稳定 ID 与树合同可迁移。
- TCO：复用当前运行时、认证、API 和 Web，不新增基础设施或生产权限面。

### 否决：前端硬编码功能树

客户端会成为第二状态真源，无法稳定测试 Evidence 等级、状态和权限边界。

### 否决：立即引入 React Flow/图数据库/Temporal/向量库

首版是几百个以下的产品能力节点，不存在图查询、长事务或语义检索压力；新增依赖会扩大
维护、供应链和权限面，违反已接受的基础设施门。

### 否决：复制 LinkFox UI 或把公开营销能力标为已接入

会造成来源、许可、平台接入和事实成熟度误导，也无法复用 KJDS 的 Ozon/RU 运营内核。

### 不行动/延期

只更新竞品文档不能满足用户对可交互树、逐功能细化和未来全球扩展合同的需求。

## 前沿技术实现边界

- 多模态：图片/视频/文档/表格进入来源专用 Evidence，再由可替换模型适配器生成候选产物。
- Agent：计划、工具选择、执行许可和回读分离；Skill 需要版本、白名单、评测、预算和回滚。
- 检索：先使用 PostgreSQL 精确/全文检索与来源过滤；只有基准证明不足才评审向量扩展。
- 工作流：先复用 Outbox、受限命令、租约和补偿；只有真实重放/SLO 压力才评审 Temporal。
- 观测：每次模型/Skill 记录版本、提示摘要、输入 Evidence、成本、延迟、QA 与人工结论。
- 前端：无 Canvas 黑盒；HTML 详情可访问、SVG 连线可缩放、键盘可操作、移动端降级为纵向树。

## 不可逆影响

无数据库迁移、无外部写权限、无第三方数据复制。新增稳定能力 ID 后不得无迁移说明地复用
或改变语义。

## 迁移与回滚

回滚时移除独立路由、运行时服务和注册表；现有经营、证据、Ozon 与 Web 工作区不受影响。
注册表纯代码资产，不保存客户或平台数据。

## 验收

- 注册表每个叶子通过结构、状态、市场、平台、输入输出、技术和边界测试。
- 原子点、价值流、经营面的 ID 唯一且无悬空引用；价值流至少覆盖研究、商品、内容、
  发布、增长、供应、履约、售后、财务、复盘与异常接管。
- 每个原子点可下钻查看真实输入输出、Evidence、Owner、失败队列、回读和 KPI；每条线
  可见入口/出口门、状态变化与异常；每个面可见真源、维度、决策、预警和写边界。
- 认证 API 返回稳定树、统计和规范哈希；匿名请求失败关闭。
- Web 支持点/线/面切换、跨层搜索、Russia/Global、状态过滤、展开/收起和逐节点详情。
- 桌面与移动截图无横向溢出，且 `implemented/ready/gated/research_only` 明确可见。
- 全量 Python/Web/PostgreSQL/OpenAPI/Git 质量门通过。

## 复审触发

- 第二个真实平台适配器进入生产；
- 能力节点超过 500 或出现真实多跳图查询压力；
- 模型输出进入真实平台写路径；
- 需要多租户能力继承或第三方生态发布；
- 官方来源、许可、数据合同或 LinkFox 产品边界发生材料变化。
