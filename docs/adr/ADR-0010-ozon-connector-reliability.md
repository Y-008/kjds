# ADR-0010：Ozon 连接器可靠性与响应证据

| 元数据 | 值 |
|---|---|
| status | Accepted |
| date | 2026-07-17 |
| owner | 工程负责人 |
| approver | 经营负责人 |
| affects | G-1 / G0 / BR-003 / P0 连接器安全 |

## 背景

Ozon Worker 已有固定超时、读请求有限退避和写请求不盲重试，但尚未形成统一的字段漂移检测、熔断状态与响应原件证据合同。只保存摘要和响应哈希不足以在字段漂移、争议或复核时重放当时的真实响应。

## 决策

1. Ozon 读请求最多尝试三次，只对传输错误、HTTP 429 和 5xx 退避；`Retry-After` 和退避等待均设上限。
2. 连续可重试故障达到阈值后，在当前隔离 Worker 进程内开启熔断；冷却期结束只允许一个探测请求。成功响应关闭熔断，探测失败重新进入冷却。
3. 平台写请求只发送一次。网络中断后的结果一律为 `uncertain`，不得自动重试；4xx、429、5xx 和字段漂移使用稳定机器错误码。
4. 每个使用中的 Ozon 端点校验最小响应结构。缺少关键容器、列表或 `task_id` 时标记 `OZON_SCHEMA_DRIFT`，不得把空值解释为成功。
5. 成功只读 run 必须先通过专用 `pilot_reader` 上传接口保存响应原件包。原件包只包含响应路径、状态码、允许的响应头和原始 body，不包含请求头、Client ID、API Key 或 Token。
6. 控制平面计算并复验 SHA-256，将原件证据以 `raw_response` 血缘连接到 run。完成 run 时，声明的 `response_sha256` 必须与已保存原件一致；摘要证据只引用原件证据，不复制原始业务字段。
7. 原件大小沿用证据上传上限，分类为 `operational`，自动删除继续禁止。失败响应正文不进入错误消息或普通日志。

## 未选择方案

- 不引入通用重试、熔断或遥测依赖；当前只有一个隔离 Ozon 客户端，标准库状态机足够。
- 不把熔断状态写入 PostgreSQL；单进程 Worker 的本地状态已经能阻止故障风暴，跨实例共享等出现真实多实例需求后再评审。
- 不允许通用证据上传接口授予 `pilot_reader`；专用路由固定来源、关系和元数据，缩小权限面。
- 不在控制平面日志或 run 摘要中保存原始响应。

## 迁移与回滚

本批不改变业务表结构。响应原件通过现有 Evidence Ledger 与 Lineage Edge 保存。回滚代码后，历史原件证据和血缘仍可读取；旧 run 保持 `raw_response_stored=false`，不得伪装成具备原件证据。

## 验收

- 429、5xx 和传输错误的有限重试测试。
- 熔断开启、冷却探测和成功恢复测试。
- 非 JSON、顶层非对象和端点关键字段漂移测试。
- 写请求传输异常只调用一次。
- 成功只读 run 缺少原件、哈希不匹配时失败关闭；上传正确原件后完成并可从 run 追到可复验 Evidence。
- `uv run ruff check .`、`uv run pytest`、完整 G-1 和 `git diff --check` 通过。

## 复审触发条件

- Ozon Worker 需要多实例并行或共享熔断状态。
- 原始响应超过当前 Evidence 上限或需要外部对象存储。
- 新增第二类 Ozon 端点或第二个平台连接器。
- 出现需要集中指标、跨服务 span 或 SLO 告警的运行压力。
