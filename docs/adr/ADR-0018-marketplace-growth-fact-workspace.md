# ADR-0018：店铺增长事实快照与多模式工作区

- 状态：Accepted
- 日期：2026-07-25
- Owner：产品与控制面负责人
- Approver：经营负责人待 G0 复核

## 背景

`MarketplaceGrowthPlanner` 已能把单次提交的成本场景、店铺指标、同行价格和 Evidence 计算为 Ozon SKU 组合建议，但调用方仍需手工携带整组数据，无法证明“当前全店方案”究竟基于哪一版店铺事实。后续店群、铺货和精品/精细化运营如果各自保存一份事实或复制规划逻辑，会造成口径漂移、跨店污染和批量自动化绕过治理。

## 决策

1. 在规划器外增加一个 `MarketplaceGrowthWorkspace` 深模块，公共接口只包含采集不可变快照、读取各 SKU 最新观测和生成最新全店计划。
2. 快照使用“来源 + 幂等键”唯一约束和规范化载荷 SHA-256；重复相同载荷返回原快照，不同载荷失败关闭。观测保留版本，不覆盖历史。
3. 生产使用 PostgreSQL 适配器；模块测试使用内存适配器。路由和前端不得直接访问存储。
4. 店群、铺货、精品/精细化和品牌运营共享同一事实与规划内核，只通过店铺范围、配额、工作流模板、权限和自动化等级形成不同工作区。
5. 第一阶段允许 `ozon_seller_api`、`ozon_export` 和 `operator_verified` 三类明确来源；当前未完成的真实 Ozon 采集器不得伪装为已连接。全部输出仍为建议，不自动改价、发布、采购或投放。

## 不建设

- 第二套商品、利润、Evidence、审批、执行或多租户事实库。
- 以店群或铺货名义降低成本权威、合规、证据、审批、回读、止损要求。
- 在没有真实店铺身份、合同和平台回读前开启批量平台写入。

## 验收

- 相同来源与幂等键的相同快照可安全重放，不同载荷被拒绝。
- 最新观测查询按 SKU 选择最新 `observed_at`，且能追溯快照、操作者和 Evidence。
- 全店计划只调用既有 `MarketplaceGrowthPlanner`，保留全部 BR-066 门禁和 `recommendation_only`。
- Web 可保存当前事实、查看最新组合并生成全店计划；初始驾驶舱不因此增加同步请求风暴。
- Alembic 升级、PostgreSQL 约束、模块测试、API 测试、Web 测试与生产构建通过。

## 回滚

停止新快照 API 后，旧手工组合规划接口仍可使用。数据库降级只删除本模块新增的快照与观测表，不改写既有 Product、Evidence、成本场景或执行记录。
