# ADR-0008：时间、金额与度量的领域语义

- 状态：Accepted
- 日期：2026-07-17
- 对应规格：`MASTER_SPEC.md` 17.1 时间、金额与数据质量
- 当前范围：供应商报价/利润场景第一批，Ozon 导入/财务账本第二批，决策/因果实验风险数字第三批，因果策略/能力经济账第四批，旧核心账第五批

## 问题

供应商报价、汇率、物流成本和利润计算同时跨币种、时区与外部来源。只依靠 API 类型或数据库 `NUMERIC`/`TIMESTAMPTZ` 不能阻止 `NaN`、无时区时间、负成本和非法比例进入事实表；一旦这些值参与利润、对账或阶段门判断，结果会看似精确但无法复算。

## 决策

1. 外部时间必须是带时区的 ISO-8601；领域入口立即规范化为 UTC，数据库使用带时区时间。无时区时间拒绝，不猜测来源时区。
2. 金额、汇率、重量、尺寸和比例使用 `Decimal`/PostgreSQL `NUMERIC`，禁止二进制浮点进入持久化事实或利润计算。
3. 所有数值必须有限；领域对象拒绝 `NaN` 和无穷值。价格、汇率、重量、MOQ 和盈亏平衡价必须大于零；成本与尺寸不得为负。
4. 单项费率满足 `0 <= rate < 1`；共同构成收入分母的费率之和必须小于 1，避免零或负分母。
5. 币种代码在入口规范化为三个 ASCII 大写字母。系统不隐式换汇；每次换算必须携带明确汇率、来源和适用日期。
6. 舍入只发生在明确的展示、结算或合同边界；中间计算保留 Decimal 精度。当前利润场景沿用既有 `ROUND_HALF_UP` 规则。
7. 领域校验是主要错误反馈，PostgreSQL CHECK 约束是绕过服务层时的防线；两层规则必须由同一迁移和测试共同验证。

## 最小实现

- `SupplierOffer` 校验并规范化报价、汇率、度量、币种和 `captured_at`。
- `ProfitInputs` 校验金额、成本和费率，并拒绝不可计算的组合费率。
- `20260717_0030` 为 `source_offers` 和 `profit_scenarios` 增加 11 条 CHECK 约束。
- G-1 使用一次性 PostgreSQL 直接绕过服务层写入负价格、`NaN` 价格和负物流成本，数据库必须拒绝。
- `20260717_0031` 为 FX、财务分录、对账容差和现金计划增加 5 条 CHECK 约束；Ozon 导入与财务服务拒绝非有限值。
- `20260717_0032` 为决策合同、预测区间、决策结果、因果实验预算/止损/观测/安全阈值增加 7 条 CHECK 约束；领域入口拒绝非有限值。
- `20260717_0033` 为策略阶段结果和能力经济账增加 5 条 CHECK 约束；领域入口拒绝非有限策略阈值/暴露/收益及非 ASCII 币种，数据库强制成本非负与净价值算式守恒。
- `20260717_0034` 为订单、费用、市场观测、机会分、旧增长实验、自动化建议和样品采购增加 7 条 CHECK；共享入口函数拒绝非有限 Decimal 和非 ASCII 币种。

## 边界与取舍

- 当前不引入通用 Money 框架、货币库或单位换算服务；在出现第二种真实会计口径或重复换算需求前，这会增加抽象而不增加正确性。
- 本 ADR 不定义法定税务舍入、银行入账日或 Ozon 结算口径；这些必须由真实一手文件和财务负责人批准。
- `effective_at` 与 `recorded_at` 的双时间语义仍由事实/证据领域负责。本批只确保供应商采集时间明确且可比较。
- 0030–0034 已覆盖当前 ORM 的显式 NUMERIC 列；未来新增金额表和字符串型数值合同必须在接入真实数据前按本 ADR 审计。结构覆盖不能据此宣称真实会计、税务或平台结算口径已完成。

## 验收

- 无时区时间、`NaN`、无穷值、负成本和非法组合费率在领域入口被拒绝。
- 绕过服务层的非法报价仍被 PostgreSQL 拒绝。
- Alembic 0034 升级、回滚、再升级通过。
- 全量测试、API/Web smoke 与清理均通过，报告保留迁移和验证字段。
