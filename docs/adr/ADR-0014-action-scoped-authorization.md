# ADR-0014：单任务、单引擎、动作作用域授权

- 状态：Accepted
- 日期：2026-07-20
- 影响：SKU-000、候选研究、采购、媒体、Listing、广告、补货、财务晋升

## 背景

研究闭环需要在真实经营证据尚未齐备时继续，但拆分 `SKU-000A/B` 会破坏任务真源、依赖统计和交接状态；实现两个 Gate 又会形成重复规则和绕过路径。

## 决策

1. 保留唯一任务 `SKU-000`、唯一 Readiness 真源和唯一服务端入口 `authorize_action(action, subject_id, actor, occurred_at)`。
2. 动作策略只区分 `research` 与 `real_execution` 作用域，不创建新任务 ID、后台、审批系统或队列。
3. 研究动作允许候选分析、报价收集、模拟利润、图片/视频生成、Listing 草稿和审批演练；产物必须标记为模拟/估算且禁止外部副作用。
4. 样品付款、正式采购、Listing 发布、广告、补货、`actual` 晋升和自动入账必须在请求时及 Worker 执行时复验。
5. 财务原件上传、预检、暂存、Evidence/哈希和人工复核不得被真实经营门阻塞；只有正式事实晋升和自动入账受严格控制。
6. 复用现有 ComfyUI 执行、Blob、Evidence、Lineage、QA、Approval、Outbox 和 LimitedExecutor；n8n 仅作为受控 API 外围的定时、通知和催办层。

## 失败关闭

- 前端隐藏按钮不构成授权。
- Worker、重试、重放、脚本、管理员入口和直接服务调用不得复用过期 READY，执行前必须重验。
- 研究记录不得原地改写为真实事实。
- 所有拒绝必须记录稳定阻塞码、策略版本、证据和复核引用。

## 验收

1. 动作—门禁矩阵是唯一策略合同。
2. 写路径清单覆盖 API、服务、Worker、Outbox、计划任务、脚本、回调、重试和正式事实晋升。
3. 自动测试证明直接 API/服务、Worker 重试、证据失效、研究转真实和重放均不能绕过。
