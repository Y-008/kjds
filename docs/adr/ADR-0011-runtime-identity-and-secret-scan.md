# ADR-0011：运行身份配置与仓库密钥扫描

| 元数据 | 值 |
|---|---|
| status | Accepted |
| date | 2026-07-17 |
| owner | 工程负责人 |
| approver | 经营负责人 |
| affects | G-1 / G0 / SEC-001 / P0 密钥与配置 |

## 背景

控制面已支持单密钥开发身份和 `KJDS_API_KEYS_JSON` 多身份，但空 JSON 对象会覆盖可用的开发密钥，未知角色也可进入配置。生产环境没有明确禁止退回共享单密钥。仓库只依赖 `.gitignore`，尚无可重复的高置信密钥扫描门。

## 决策

1. `KJDS_API_KEYS_JSON={}` 视为未配置多身份，允许开发环境回退到 `KJDS_API_KEY`；非空映射继续优先。
2. 身份配置只接受系统已声明角色；未知环境、未知角色、空 actor/role、非法 JSON 和占位密钥启动失败关闭。
3. `production` 必须使用非空多身份映射，禁止只使用共享 `KJDS_API_KEY`；若设置 Web 代理密钥，它必须同时出现在映射中。
4. 运行配置校验只输出环境、身份数和非敏感角色摘要，不输出密钥、数据库 URL 或 provider token。
5. G-1 使用标准库扫描 Git 已跟踪文件和未忽略的新文件：禁止跟踪 `.env`、私钥/证书容器、数据库 dump/backup，并检查高置信 token/私钥签名。示例、测试假值不靠弱熵启发式判断。
6. 不引入 Vault、云 KMS、通用 secret scanner 或新依赖；真实托管部署需要轮换、撤销和托管密钥时再评审。

## 验收

- 空 JSON 映射可安全回退开发密钥。
- 非法 JSON、未知角色、占位密钥和 production 共享单密钥均失败关闭。
- 多身份模式下 Web 代理密钥未登记时失败关闭。
- 专用 worker 身份越权测试继续通过。
- secret scan 对禁止文件和高置信 token 可重复失败，当前仓库通过。
- 全库测试、G-1 与 `git diff --check` 通过。

## 复审触发条件

- 首次托管生产部署或需要自动轮换/撤销。
- 密钥数量、团队人数或审计要求超过环境变量配置能力。
- 发生凭证泄露、需要 KMS/HSM 或第三方合规认证。
