## Gate 依赖

`G-1 → G0 → G1 → G2 → G3 → G4 → G5 → G6 → G7 → G8`

允许在不制造重做的前提下提前准备后续数据合同和模板，但不得提前宣告后续 Gate 通过。

## G-1：可信工程基线（2–3 天）

- 将现有 13 个修改和 21 个未跟踪条目按领域分层审阅并形成可回滚提交。
- PostgreSQL 实际迁移到 `20260716_0010`，验证全新升级、回滚与重新升级路径。
- 通过专用临时数据库运行 PostgreSQL/API/UI smoke，并执行 44 项受版本控制的自动测试；同时验证源文件证据化、SKU Episode 幂等录入、Passport 人工审核与版本冲突保护、三供应商证据化比价、采购申请幂等与双人审批、商品—供应商—报价绑定、利润假设证据门、G0/G1 准入投影、Passport 证据准入、Ozon 正式事实晋升、证据化费用/FX、三方对账和 13 周现金流。
- 修正静态 `ENVIRONMENT_GATE.md` 与实时环境不一致问题，状态由检查结果生成。
- 退出证据：提交哈希、迁移输出、健康检查、API/UI 截图或测试记录。

## G0–G1：合法启动与商品准入（3–5 周）

- 明确经营/项目/商品合规/财务/工程负责人。
- 核验 Ozon 账户、合同、权限、履约和收款路径。
- 录入三个真实候选 SKU，完成商品、俄罗斯合规、样品/质量 Passport。
- 每个 SKU 至少三家真实报价，记录黄金样、实测重量尺寸、包装测试和主备物流。
- 退出证据：3 个 Episode Evidence Package 和 Gate Review 签字。

## G2–G4：从上架到人民币到账（7–11 周）

- Ozon 官方只读同步；CSV/XLSX 暂存行必须转为正式订单、费用、退货、物流和结算事实。
- 俄语关键词、Listing 和素材经母语/IP/事实一致性审核。
- 一笔测试单和至少一笔真实买家订单走完履约。
- 导入结算与银行文件，完成订单—结算—银行三方对账和实际 CM3。

## G5–G7：验证 Agent，而不是展示 Agent

- 先运行 14 天影子模式，再开放低风险提醒、草稿和提案。
- 高风险生产写入仍禁止；只有完整执行链和故障注入通过后才逐项启用。
- 三 SKU 都完成同口径复盘后，才判断是否具有复制性。

## 冻结区

G7 之前冻结多租户、第二国家/平台、SDK/市场、跨租户网络效应、独立向量库、Temporal 和复杂多 Agent 委员会。出现真实重复需求和明确商业模式后，再通过 ADR 和 G8 解冻。
