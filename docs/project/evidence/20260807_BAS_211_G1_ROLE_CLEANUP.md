# BAS-211 G-1 Role Cleanup Remediation

- Scope: `scripts/manage_g1_database.py`, `scripts/verify-g1.ps1`, the GDC PostgreSQL fixture, the G-1 harness contract, and this Evidence only.
- Root cause: an interrupted run could leave receipt-owned fixed roles with memberships or `public` schema ACLs in an admin database. The dedicated GDC fixture then attempted blind `DROP ROLE` before the G-1 lease phase and failed with `DependentObjectsStillExist`.
- Harness boundary: the holder of `Global\KJDS-G1-Verification` performs receipt/CAS guarded recovery before the dedicated GDC suite. The fixture never adopts or deletes an unknown fixed role or schema.
- Ownership boundary: recovery requires the exact lease/receipt token, exact role comments and attributes, exact role set, and exact receipt-owned database or GDC schema. Unknown, uncommented, or preexisting resources observed during preflight fail closed without mutation. The primary transaction revalidates the receipt and dependencies before role deletion; after preflight, only the idempotent revoke of a receipt-owned `public` schema ACL may commit before that revalidation and is safe to replay.
- Dependency boundary: recovery classifies role memberships and `pg_shdepend` rows. It revokes only run-internal membership/admin options and the explicitly admitted `public` schema ACL. Any unrelated owned schema, table, function, default ACL, object, or non-admitted dependency blocks recovery. `DROP OWNED BY` is not used.
- Atomicity: target database removal remains an idempotent autocommit phase because PostgreSQL requires it. The subsequent membership cleanup, all fixed-role drops, receipt flag update, and lease deletion execute in one primary-admin transaction. GDC schema removal, all GDC role drops, and GDC receipt deletion also execute in one transaction.
- Interruption evidence: real PostgreSQL tests cover crash immediately after lease acquire, failure after the first G-1 role drop, failure after GDC schema removal and the first GDC role drop, and fixture setup failure after GDC acquisition. Each failed transaction preserves the complete receipt/resource set for retry; retry removes all owned resources and a second recovery is a no-op.
- Preservation evidence: real PostgreSQL tests retain unknown/wrong-comment resources and reject a run-owned role that owns an unrelated sentinel schema without changing the role set, sentinel, ACL, database, or receipt.
- Current focused gates: G-1 harness contract `14 passed`; isolated GDC PostgreSQL contract `84 passed, 12 warnings`; Python compile, Ruff, PowerShell parser, and diff checks pass. The secret scan passed for `1407` non-ignored worktree files and `1403` historical paths. Five candidate files matched their frozen SHA-256 values across a five-second resample (`UNSTABLE_COUNT=0`) with `staged=0`.
- Boundary: no migration, API, OpenAPI, runtime product, or business-data change; external business writes remain false.
- Release state: implementation is not staged or committed. A fresh G-1 must run only after independent feature/release signoff and against the resulting final HEAD.
