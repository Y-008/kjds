## 决策

账户、合同与 API 能力已不再是完全未知，但不能据此放行 G0 或自动上新。现有 Key 权限过宽，且没有独立审批主体。下一步必须：

1. 由账户负责人确认 7 个 Key 的真实调用方。
2. 经明确批准后创建专用只读 Key，只授予当前只读合同需要的角色。
3. 轮换并撤销闲置宽权限 Key；密钥只进入本机/托管秘密存储，不进入仓库、日志或对话。
4. 导出长期商品、订单、费用、退货和结算原件，哈希固化后进入 Evidence Gate。
5. 将现有 18 个商品只作为历史目录、经营基线与竞品对照；新的三个上新候选必须另行取得需求证据、可采购性、每个候选三家真实报价、合规红线和风险调整后 CM3，不能由旧目录自动晋升。

## 最小接入交接包

账户负责人完成的人工动作仅限以下四项，任何一步都不得在对话或仓库粘贴密钥：

1. 在 Ozon Seller 中确认现有 Key 的调用系统、负责人、最后使用时间和保留理由；清单只记录平台脱敏引用，不记录 Key 值。
2. 明确批准后创建独立的 KJDS 只读身份，只授予产品读取试运行所需角色；订单、财务、库存等权限按后续已批准 Pilot 分批增加，不一次授予全部角色。
3. 将 `OZON_CLIENT_ID`、`OZON_API_KEY` 仅写入本机未跟踪的 `.env` 或托管秘密存储；先运行受限的单商品属性 Pilot，再扩大到最多 3 个候选 SKU。
4. 从官方后台导出商品、订单、费用、退货和结算原件，保留原文件、导出时间、选择条件和 SHA-256；浏览器手抄数字不能代替原件。

工程验收顺序：

```text
身份调用方盘点
→ 独立批准专用只读身份
→ G0 Gate Review 与 Pilot 审批
→ 单 SKU 读取
→ 原始响应包哈希复验
→ 独立 Claim Review
→ 最多 3 SKU 小批量读取
→ 长期原始导出导入
→ CM3 与可售性决策
```

接入成功标准：密钥扫描仍通过；运行环境不输出凭证；Pilot 只访问批准的只读端点；原始响应包可复验；摘要 Claim 由不同主体审核；任何正式事实晋升仍为显式人工决定。任一条件失败立即停止，不扩大权限、不执行上新。
