## 产品信息架构

前台由单页长滚动改为同一认证平台内的十个任务工作区：

1. 经营总览：真实 Gate、候选、审批、事故、Evidence、连接健康和 Agent 简报；
2. Ozon 增长：把已有全成本场景与同行快照编译为价格、内容、评价和广告建议；
3. 利润与结算：实际成本、费用映射、结算、银行和 FX 依据；
4. 数据与证据：Ozon 原件预检、导入、Evidence 固化和独立复核；
5. 选品研究：需求依据、三候选、五指标和三报价交接；
6. 商品与内容：SKU Passport、七类原图、图片 QA、俄语 Listing 和发布审批；
7. 1688 与供应链：供应商、三报价、十五项成本、样品和备用供应商；
8. AI 决策与实验：决策合同、因果实验、策略影子、观察和复盘；
9. 审批与执行：双人审批、执行计划、一次性命令、回读、回滚和事故；
10. 系统运行：研究/真实执行 Gate、运行异常、只读试点和连接健康。

导航使用可分享的 Hash 工作区地址，桌面为常驻侧栏，移动端为横向任务导航。每个工作区都显示当前作用域和副作用边界，原有领域面板及业务表单全部保留。

## 现有 Ozon SKU 增长

新增非技术增长表单，提交至既有 `POST /v1/marketplace-growth/portfolio-plan`：

- 选择已有 1688/供应链全成本利润场景；
- 输入至少三条同规格同行价格、库存、近 14 天订单、评价、评分、内容分、真实转化率、合规风险和 Evidence IDs；
- 服务端输出同行 P25/P50/P75、目标 CM3 底价、建议测试价、保本 ACOS、目标 ACOS、最大单笔广告费、最大 CPC、十二项增长门禁、七类图片计划和有序动作；
- UI 明示自动改价、自动广告、自动发布均为关闭；
- 结果只有 `recommendation_only` 权限，不调用命令、写入尝试或平台回执接口。

## 审批与真实写入

审批与执行工作区把阶段拆成提案、独立批准、单次执行和回读观察。真实 Ozon 写入能力没有被删除或关闭，但仍只能消费既有受控链：

`Evidence → 草稿 → 独立审批 → 执行计划 → 单次命令 → 写前快照 → 平台写入 → 回读 → 观察/补偿`

该工作区不新增直接批准或立即发布捷径；实际审批继续回到对应商品、供应链、财务、实验和系统领域表单。

## 仍需真实经营输入

工程平台已能承载真实店铺经营，但“出单”不能由软件保证。真正进入价格或广告实验前仍需把对应 SKU 的精确同款同行快照、实际落地成本、店铺转化和预算止损线固化为 Evidence，并由经营责任人批准。平台会给出最优的可验证下一动作，不会用未经证实的数据替用户花钱或改店铺。
