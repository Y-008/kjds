## 风险

`BAS-049` 已保证只有双人复核接受的真实需求报告才能满足 `SKU-000`，但候选五指标此前没有显式保存该报告 ID。只检查“系统中存在某份已接受报告”会允许不同候选、不同观测或后续交接暗中混用来源，使需求结论与报价、利润计算之间失去可审计的因果链。

## 已实现合同

- 候选录入、复评和三报价人工交接必须显式提交 `demand_report_evidence_id`。
- 服务端每次重新验证该报告仍是有效 `source_report`，Blob、来源元数据和不可变复核均有效，且至少一份接受、不存在拒绝。
- 五类观测都保存同一报告 ID；缺失或混用报告的观测不参与候选判断，不能被其他候选或历史观测补齐。
- 候选评估响应和三报价交接响应返回报告 ID，Web 只允许从当前已接受报告列表中选择，并在交接时复用评估结果里的 ID。
- 人工确认交接后，商品新增 `candidate_basis` 与 `demand_report_basis` 两条独立血缘；`SKU-001` readiness 同时重新验证两条血缘。
- 报告后来被拒绝、损坏或失去接受条件时，既有候选商品立即不再计入合格候选，不依赖前端状态缓存。
- 交接仍只创建 `CANDIDATE` 商品和采购比较工作区，不自动采购、不生成平台写入、不自动上架。

## 验收覆盖

- 待复核或未接受报告：候选录入阻断。
- 五类观测绑定报告 A、评估请求报告 B：全部观测失效并要求重新收集。
- 有效报告：评估返回同一报告 ID；三报价人工交接保持该 ID。
- 公开样例或无效报告：`SKU-000` 与 `SKU-001` 同时保持阻断，合格候选数为零。
- 候选交接重复提交：幂等，不重复创建商品或事件。
- 报告缺失、损坏、待复核或被拒绝：readiness 失败关闭。
- Web 契约验证报告选择、请求绑定、结果显示和交接复用。
