# BAS-094 物流计费重与利润场景闭环工程证据

- 日期：2026-07-26
- 需求：BR-069 / BAS-094
- ADR：ADR-0020
- 版本：Control Plane `0.52.0`

## 已实现

1. 新增 `LogisticsQuoteWorkspace` 深模块及 PostgreSQL 适配器，线路档位和成本测算均不可变、可追溯、可幂等重放。
2. 线路模型覆盖承运商、路由、服务、平台、计价/申报币种、每 kg 价、每票固定费、最低收费、体积重除数、计重进位、重量/尺寸/三边和/货值边界及有效期。
3. 确定性 Decimal 引擎以未提前舍入的体积重计算计费重、进位重量、线路币种金额和 CNY 金额；过期或越界失败关闭。
4. 三家供应商比价可选择版本化线路，以每家商品的实测重量和尺寸生成单件物流快照，并用其替代手填国际运费进入既有 15 项成本与 CM3。
5. `international_logistics` 固定写为 `estimate`，Evidence 自动指向线路报价原件；只有独立复核的承运商最终账单可成为 `actual`。
6. 统一经营前台增加线路固化、物流测算、结果卡和三家比价线路选择。页面明确 AI 只解释异常、建议包装复核和多线路比较。
7. 决策辅助接口只返回确定性事实、体积重/进位/最低收费告警和建议，不授予利润写入、采购、定价、上架或投放权限。
8. CNY 线路强制汇率为 1 且拒绝多余 FX Evidence；非 CNY 线路必须提交独立 FX Evidence，测算与利润场景同时保留该汇率血缘。
9. 线路原件只接受 A/B 级承运商报价来源；汇率快照还必须处于有效期内，且元数据中的基础币种、CNY 报价币种及汇率值与测算完全一致。
10. 利润场景通过可空数据库外键引用物流测算；引用时强制校验 Ozon、RU、RUB、售价申报价值、单件重量和三边尺寸，避免跨档位或跨市场误用。

## 真实资料审计

- 只读分析了 Ural、CEL、RETS 和 GUOO 的代表性物流报价/测算工作簿，未改写或导出原件。
- 发现并验证了按实重、体积重除数 `12000`、按 0.1kg 进位、每票固定费、最低收费以及重量/货值/尺寸分档等不同规则。
- 第一条规范化真实线路使用 GUOO Ozon realFBS 工作表的明确档位；原始工作簿先进入 Evidence Ledger，线路只引用已核对的工作表和单元格区域。

## 明确边界

- 不在生产服务中执行第三方 Excel、宏或外部链接。
- 不把报价线路、AI 建议或测算结果冒充承运商最终账单。
- 不自动选择物流商、采购、付款、改价、上架或投广告。
- 一张线路卡只代表一个明确档位；含义不明、继承单元格不清或缺有效期的规则不会被自动批量导入。

## 审查结论

- P0：无。
- P1（已处理）：初始幂等摘要直接使用 Decimal 文本，导致 `2291` 与 `2291.00` 被误判为不同输入。改为规范数值摘要、增加等价小数位回归，并仅更新本轮创建的线路/测算摘要；Evidence 与业务金额未删除或改写。生产浏览器随后重放成功。
- P1（已处理）：初版利润引用只核对重量/尺寸，且任意有效 Evidence 都可误选为线路或汇率依据。现已增加利润场景完整作用域/申报价值校验、线路与 FX Evidence 语义白名单、A/B 等级、FX 有效期/币种对/汇率值校验。
- P2（已处理）：利润场景的物流测算引用从 JSON 内嵌字段提升为带索引的数据库外键；旧行仍兼容读取。
- P2：无。
- Info：真实数据库尚无 Product、Supplier Offer 或 Profit Scenario；这是既有候选/三报价 Gate 的真实阻断，不以目录商品或物流表自动造数绕过。
- Info：该能力减少头程估算误差，但不改变 BR-057 的实际成本权威要求。
