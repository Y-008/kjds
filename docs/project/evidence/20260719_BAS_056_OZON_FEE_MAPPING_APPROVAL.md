# BAS-056 Ozon 实际费用码映射审批门

## 交付结论

Ozon 费用导入现在必须依次经过：不可变原件、非上传者来源复核、实际费用码识别、逐码版本化映射批准、正式事实晋升和财务分录摄入。来源复核本身不再足以晋升费用事实。

## 失败关闭边界

- 通用 `POST /v1/finance/fee-mappings` 拒绝 `provider=ozon`。
- 专用审批只接受已被独立复核并接受的 Ozon 费用导入。
- 只能批准该导入中真实出现的 `fee_type`，不能提交臆造代码。
- 上传原始报表的人不能批准其费用映射。
- 批准 Evidence 必须同时连接原始报表、导入任务和版本化映射；原件损坏、复核失效或任一血缘缺失时映射立即视为无效。
- 映射批准不会自动晋升事实、写入账本、启动对账或触发平台操作。

## 人工界面

复核人接受 Ozon 费用原件后，页面只展示文件中实际出现的费用代码、行数和覆盖状态。复核人逐码选择会计类型、金额符号、有效期并填写依据；仍由后续明确动作晋升事实。

## 验证

- 单元测试覆盖来源未复核、缺少映射、自审批、臆造代码和血缘被移除后的失败关闭。
- API 合同测试覆盖通用 Ozon 映射旁路被拒绝。
- Web 合同测试覆盖实际费用码读取、专用映射审批和“不会自动入账”的用户提示。
- G-1 端到端验收走完整费用导入、独立复核、旁路拒绝、专用批准、事实晋升、账本摄入和三方对账路径。
