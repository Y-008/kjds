## 方法循环

`经营目标 → 硬约束/预算/最大损失 → 假设 → 证据 → 小实验 → 审批 → 命令 → 结果 → 复盘`

每一轮必须产生可审计记录。没有结果证据的讨论只能更新假设或未知项，不能自动升级为事实或开发承诺。

## 十六条长期原则

1. **目标链闭合**：每个任务必须追溯到经营目标、当前 Gate 和明确验收。
2. **四类对象分离**：事实、推断、决策、动作分别记录；Agent 不得把推断写成事实。
3. **证据分级**：A级为官方订单/结算/银行/供应商账单；B级为可信第三方估算；C级为网页观察；D级为 AI 推断。低级证据不能覆盖高级证据。
4. **未知优先**：缺失硬事实标记 `UNKNOWN` 并进入未知队列，不自动补全。
5. **证据可重放**：保存来源、抓取时间、哈希、原始快照、提取值、解析版本、可信度和责任人。
6. **双时间**：现实生效时间 `effective_at` 与系统获知时间 `recorded_at` 分开，支持迟到退货和结算重放。
7. **确定性优先**：金额、币种、FX、库存、价格底线、合规硬规则、权限、幂等和状态机使用代码/Schema/规则；LLM 只负责理解、生成、建议和审查。
8. **经营账本**：订单—平台结算—银行到账三方对账；未知费用不能长期塞入“其他”。
9. **利润加现金**：同时看 CM3、现金转换周期、库存周转和 30/60/90 天资金缺口。
10. **三个 Passport 硬门**：商品事实、俄罗斯合规、样品/质量不完整或未人工批准不得上线。
11. **受控执行**：Agent 只提出标准 Command Proposal；Policy 校验、风险评级、审批、执行、复读验证、补偿/回滚缺一不可。
12. **实验可证伪**：建议必须包含预期增量 CM3、证据、对照、时间窗、最大损失和停止条件。
13. **Build Harness 与 Run Harness 分离**：前者管理开发、测试、发布；后者管理经营数据、策略、审批、执行和熔断。
14. **独立 Oracle**：黄金账单/CSV、官方固定响应、人工确认结果和错误注入样本不由实现 Agent 随意修改。
15. **完成不靠自报**：需求合同、DoD、测试、迁移/回滚、真实接口验证、证据包和人工批准共同决定状态。
16. **方法论版本化**：变更记录原因、证据、影响、失效条件和复审日；只有真实结果或法规/平台事实变化才升级方法。

## 事实写入合同

任何进入事实层的数据至少包含：

- `fact_id`、对象类型、稳定业务标识；
- 原始值、标准化值、单位、币种；
- `effective_at`、`recorded_at`；
- `source_uri` 或文件标识、内容哈希、解析版本；
- 证据等级、可信度、责任人；
- `supersedes`、失效原因和复审状态。

## 建议与动作合同

任何 Agent 建议必须明确：输入事实、仍未知字段、预计收益、风险、最大损失、停止条件和人工决策点。任何外部写动作必须具有幂等键、审批标识、执行前状态、执行后复读、结果哈希和补偿路径。

## 每周复审

每周只回答六个问题：

1. 当前 Gate 的退出条件还缺什么？
2. 哪些“完成”没有证据？
3. 哪些未知项正在阻塞经营，而不是阻塞漂亮架构？
4. 预测 CM3 与实际结果偏差来自哪里？
5. 哪些任务应删除、降级或冻结？
6. 方法论是否因真实证据发生变化？
