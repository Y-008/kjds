## 一句话目标

用不超过三个真实 SKU，在受控损失范围内，验证从商品证据、俄罗斯准入、内容上架、订单履约、平台结算到银行到账和人民币 CM3 的可复核闭环。

## 成功定义

项目成功不是“功能数量多”，而是同时满足：

1. 三个 SKU 均有商品、合规、样品/质量 Passport，硬事实可追溯且经人工批准。
2. 至少一个完整订单周期能从供应商证据追到 Ozon 订单、费用、退货、结算、银行到账和人民币 CM3。
3. 订单费用解释率不低于 99.5%，订单—结算—银行汇总差异不高于 0.3%，未知费用独立隔离。
4. 金额使用 Decimal，并携带币种、汇率来源、汇率日期和证据。
5. 高风险动作经过 Command Proposal、Policy、审批、执行、复读验证和补偿/回滚。
6. 至少完成两个有对照、最大损失和停止条件的受控实验，评价指标是增量 CM3 而非采纳率。

## 当前边界

### 必须完成

- 真实 SKU、供应商、样品、包装、重量尺寸、合规和素材权利证据。
- Ozon 官方只读同步或受控文件导入，形成正式订单/费用/结算事实。
- 订单—平台结算—银行到账三方对账。
- 预测与实际 CM3、13 周现金流和异常队列。
- 身份可信的审批、Kill Switch、幂等和审计事件。

### 明确不做

- 多租户、计费、SDK、插件市场和跨租户经验网络。
- 第二国家/第二平台和全渠道归因。
- 多 Agent 委员会、企业级数字孪生、资本配置大脑等独立产品化模块。
- Redis、Kafka、Kubernetes、Temporal、独立向量数据库和本地模型运行时，除非单独 ADR 获批。
- 把个人订阅、共享 OAuth 或第三方中转账号作为生产模型供应路线。

## 经营反需求

- 不用 AI 猜测 SKU、成本、重量尺寸、证书号、库存、底价或物流参数。
- 不把网页观察、第三方估算或 AI 推断覆盖官方订单、结算、银行和供应商账单。
- 不以“接通目录”“成功导入暂存区”“页面能打开”宣称经营闭环完成。
- 不让 Agent 直写生产平台或生产数据库。
- 不为漂亮架构提前引入与当前 Gate 无关的基础设施。
